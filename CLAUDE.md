# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Layout

Two independently deployed apps live in one repo:

- **Root (`src/`, `public/`)** — Astro 5 static site (Svelte 5 islands, Tailwind 4, MDX content). Built to `dist/` and deployed to Cloudflare Workers Static Assets (`wrangler.jsonc`). This is krystianslowik.com.
- **`backend/`** — Express + TypeScript chat API ("chat-api"). Proxies the słowik chat to OpenAI, rate-limits, optionally logs to MySQL. Deployed to the k3s homelab via `backend/Dockerfile` + `backend/k8s/` manifests, reachable as `chat-api.krystianslowik.com`.

`design/` is design-lab material (interactive HTML studies + the flight-sim harness) — reference, not part of the build. It predates the 2026-07 parrot→słowik rebrand and deliberately keeps its historical `parrot-*` file names (the decision record is `design/slowik-rebrand.md`). `docs/` holds plans and design records (`docs/plans/`) — prose only, not a build source. `dist/` is build output.

### SEO / discovery layer

Head metadata has ONE owner: `src/components/SEO.astro` (title, description, robots, all OG + Twitter + `article:*`, `theme-color` `#f2f0ea` — the paper `--color-bg` in sRGB; the same value lives in `site.webmanifest`, and the bird's ink `#954e00` (`AMBER` in `slowik.ts`, `favicon.svg`, the icon PNGs, `favicon.ico`) is `--color-accent` in sRGB — every one of those is a hand-synced copy of a `global.css` token, so a token change means updating them all). `public/og.png` is a headless-Chrome shot of a throwaway card page (recipe: Task 9 in `docs/plans/2026-09-03-paper-craft-pass.md`), quantised to a 96-colour palette; re-shoot it when the name, role, doc number or tokens change. `Base.astro` passes its reconciled Props (`title, description, canonical, type, image, imageAlt, noindex, article`) through to it and separately renders the JSON-LD from the `schema` prop. Do NOT add meta tags anywhere else — widen `SEO.astro` + the `Base` Props together. Structured data (JSON-LD) is built by `src/lib/schema.ts` factories (`homeSchema`/`postSchema`/`writingIndexSchema`) from `site.ts` — every graph embeds the full Person node (validators reject bare `@id` refs across pages). Pages pass `schema={...}`; posts also pass `type="article"` + `article={...}`. `noindex` (404) emits `<meta robots noindex>` and suppresses the canonical.

Discovery files live in `public/` (copied verbatim): `robots.txt` (allow-all incl. AI crawlers + `Sitemap:` → `sitemap-index.xml`), `site.webmanifest` + icon set, `.well-known/security.txt`, an IndexNow key file. `llms.txt` + `llms-full.txt` (llmstxt.org) are NOT static: `src/pages/llms.txt.ts` and `llms-full.txt.ts` generate them at build time from `site.ts` (the full form also reads the writing collection), so they cannot drift. The sitemap gets real `lastmod`/priority via `astro.config.mjs`'s `serialize()` (reads post frontmatter dates at config time, since `astro:content` isn't importable there); `trailingSlash: "always"`. RSS is `src/pages/rss.xml.ts`. Every list of posts (RSS, the Record section, the archive, prev/next on a post, llms-full) comes from `publishedPosts()` in `src/lib/writing.ts` — there is one ordering. Fonts are self-hosted via `@fontsource*` `@import`s in `global.css` (NO Google Fonts — the site claims "no trackers"): JetBrains Mono 400/500/600 and Newsreader Variable roman + italic. Tailwind class detection is scoped to `src/` via `@import "tailwindcss" source("../")` — `docs/` and `design/` are prose and reference studies, never sources. Scroll reveals are CSS + IntersectionObserver (`html.reveal-armed`, armed by an inline head script only under motion-OK; `.reveal-fallback` 3s failsafe) — GSAP was removed. Owner-only deploy actions (not in-repo): Google Search Console + Bing Webmaster verification & sitemap submit, IndexNow ping after deploy, and confirming Cloudflare's "Block AI bots" is OFF + apex/HTTPS redirects.

## Architecture Notes You Can't See From File Names

### The słowik is a system, not a decoration

The mascot is **the słowik** — a 1-bit amber pixel bird (słowik is Polish for nightingale, and the owner's surname; in copy it is always lowercase with the article, "the słowik" — capitalized "Słowik" means the human). It was rebranded from "the parrot" on 2026-07-04 (decision record: `design/slowik-rebrand.md`; the honesty framing is Andersen's clockwork nightingale — "sings only what it was taught"). NOTE: the sprite ART is still the original crested silhouette (crest, hooked beak, round eye) — a plainer nightingale draft was drawn and then **rolled back by owner preference** (2026-07-05), so the słowik is named for the nightingale but drawn as the original bird. It appears in several places, all driven from two libraries:

- `src/lib/slowik.ts` — sprite geometry rasterised to 1-bit at runtime. The "shader" is `buildBase`: one amber ink, tone via a **4×4 ordered (Bayer) dither** — draw functions paint in greys (`#fff` solid, `#bbb`~75%, `#888`~50%, `#555`~25%) and the quantiser keeps that fraction of each cell, still literally 1-bit-per-pixel amber. Flight poses (`Wing` = `up|mid|down|glide|tuck|flare`): `glide` a long blade held ABOVE the belly-shade band (below it, dither dissolves it into `mid`), `tuck` a lean dive-dart with speed-streaks and a SHORT rib slit (a full-length rib splits the dart into slivers), `flare` the raised-wing airbrake — deliberately the `up` wing polygon (a forward-thrown wing overlaps the head and turns to mush at 1-bit); its identity comes from the fanned tail + feet (the only pose with feet). The flight head is drawn in a counter-rotated sub-frame so the **gaze stays near-level while the body pitches** (real gaze stabilization). Exposes `mountHead` (the SheetFrame mark, via `SlowikMark.astro`), `mountPerched` (404), `mountLoader` (splash), plus `buildBase`/sizes used by the flight engine. `drawFull`/`drawHead` use no grey, so they're unaffected by the multi-level dither. The head sprite is the **original crested design**: two erectile crest triangles (`crestUp` raises them), a hooked beak, a single punched round eye (r2.2), and a downward tail (`tailFlick` displaces its tip in X). A nightingale redraft (crestless, straight bill, ringed eye, up-cocked tail) was tried and reverted — do not re-apply it without the owner asking.
- `src/lib/slowikFlight.ts` — the physics flight engine (exported primitives: `stepFly`, `newFly`, `TUNING`, plus `SONGS`, the speech-bubble song bank, and `FEET`; the dead `WireParrot` class was deleted in the rebrand). **Frame-based integrator at a FIXED 20Hz tick with render interpolation** — never step it per-rAF-frame (display-dependent, runs ~4x fast at 60Hz). Horizontal motion rides the engine's own forward speed; landing uses a parking latch + wire-floor + flare. Every state change must clear `parking`/`forceLand`/`legT` or the bird strands mid-air.
- `src/lib/slowikCompanion.ts` — **THE bird: a page singleton** (`getSlowik()`, guarded on `window.__ksSlowik`). One companion for the whole journey, in viewport coordinates: it perches on `[data-perch]` anchors (section rules: the case-file articles, the Record head, the HEAD row, the Record list's post titles, the Contact block; the hero SURNAME — `data-perch="name"`, the OG spot and boot perch, biased +120 so it wins whenever the hero is on screen; the chat `wire`; the footer), rides them while you scroll, and flies (same engine) to the next perch when its branch leaves the viewport — including mid-flight retargeting when an instant scroll teleports the target away. Perch preference lives in `bias()` (wire 420 > footer 160 > name 120). There is no sticky nav bar (the `<nav>` inside SheetFrame is the page-index tile, items from `site.nav`): `SheetFrame.astro` is a fixed, pointer-events-none frame (`data-sheet-frame`) whose four frosted tiles (`.frame-tile` + `data-frame-tile`: mark, page index, clock, revision) are the only things that occlude the bird. The bird renders at z 35 — BELOW those tiles (z-40): **owner's explicit call — the bird passes UNDER the frosted tiles, never over the menu** (do not "fix" this by raising z). The hit box is clipped against the tiles' live rects, trimming from above or below depending on where the tile sits, so the occluded part of the sprite is not tappable and taps on the page-index tile always reach the menu. The chirp bubble is a paper pill (hairline, 92% paper) so it stays legible over the two inverted ink panels; under reduced motion it fades without rising. **Vertical travel is physical, not a lerp** (`VT` block, redesigned — see the "COMPANION VERTICAL V2" battery): landings DECELERATE to a near-stall via a stopping-distance flare that bleeds the bob's descent to ~0 (not the old accelerate-into-then-clamp thud); climbs are real **flap-bounding** (a burst gains height, wings fold and the body falls a visible scallop, then re-flaps) with peak climb speed < dive so the effort reads; climbing costs forward speed; pitch tracks vertical SPEED (unsaturated); per-leg jitter so repeated hops aren't identical. Touchdown gates on soft rendered speed. **Smoothness layer** (render-only, no physics): takeoff has a 100ms crouch (`crouchT`/`pendingLaunch` → `doLaunch`), the touchdown snap is blended out over ~120ms (`setX`/`setY` decaying render offset — never let landing pop in one frame), and sprites are memoised in `spriteCache` with pitch quantized to 0.04rad (a cache key change is the only thing that redraws — kills per-frame rasterization churn and sub-pixel edge boil). If the only perch is beyond the viewport (perch desert), the bird flies out of sight and settles there silently — never hover-lands at the edge (that teleports).

**Scroll-follow** (`onScroll`/`updateScroll`/`enterFollow`/`launchFollow`/`followTarget`): while you scroll, the bird does NOT chase perch anchors (they scroll away faster than it flies — that made it vanish off the top). Instead it flies to the READING LINE in viewport space (`innerHeight*READ_LINE`, near-stationary) and HOVERS there, visible, chirping to guide — then perches on the nearest anchor when scrolling stops. Take-off needs a real gesture (`scrollAccum > TAKEOFF_PX`, ~1.5 wheel notches, so casual notch-reading just rides the branch) or `perchLeaving()` (direction-aware edge exit). `enterFollow` clears `parking`/`forceLand`/`legT`/`catchT` — hijacking a landing into follow must not strand the bird in flare pose (the strand invariant applies here too). `choose()` early-returns while scroll-follow owns the bird and while `asleep()`; the follow lead is slewed (no reversal yo-yo); reduced-motion never follows (and a mid-session toggle re-settles it). The chat registers a `wire` perch and pulls the bird to new cards; the footer perch sleeps after 23:00 Europe/Berlin. `SlowikChat.svelte` does NOT own a bird — never add a second one. Booted from `Base.astro`; destroyed on `astro:before-swap`.

Tuning changes go through `design/parrot-flight-sim.js` (deterministic node harness, `node design/parrot-flight-sim.js` — the harness keeps its pre-rebrand filename) BEFORE touching `slowikFlight.ts` or the companion's `VT` vertical model. The live model is the **"COMPANION VERTICAL V2"** battery (`runCompanionLegV2`, a 1:1 mirror of `slowikCompanion.updateFlight`); the "COMPANION VERTICAL" (V1) block above it is the pre-redesign baseline kept for A/B. Sprite/pose geometry can't be validated in the sim — render it in-page (drive `window.__ksSlowik`, set `wing`/`rPitch`, `renderSprites()`, screenshot) since `buildBase` needs a DOM canvas. The interactive reference is `design/chat-wire-natural.html`.

### The chat contract

`src/components/SlowikChat.svelte` (the only hydrated island, `client:only`) renders the conversation as cards on a wire with the physics bird. It POSTs `{conversation: [{role, content}]}` to the backend and expects `{message}` back (`src/lib/chatApi.ts`; override endpoint with `PUBLIC_CHAT_API_URL`). The wire is user-scrollable left-right, but it is a **transform camera, NOT a native scroll container** (native `overflow-x: auto` would clip expanded cards vertically and break the bird's anchor math): wheel/trackpad deltaX and pointer-drag (with slop, click-swallowing, velocity smoothing, a hold-means-stop check, and a decay glide; none under reduced motion) move `camX` clamped to the conversation extent — drags may rubber-band 0.3x past the ends and spring back on release. Glide and spring are **time-based (exp decay by dt), never per-frame** — per-frame factors run ~2x hot on 120Hz phones; the motion math is mirrored 1:1 in `design/wire-scroll-sim.js` (node, deterministic) — tune there first, like the flight engine. Also: `.wire-world.manual` kills the 0.6s camera transition while the user owns it, `touch-action: pan-y` on the stage keeps vertical page scroll native, and the bird's wire anchor reads `camX` live so it rides the wire during manual scroll. The wire's vertical anchor is read from the drawn rail (`railEl.offsetTop`) and the compact flag from `matchMedia("(max-width: 639px)")`, the same breakpoint as the CSS — never derive layout from the stage's width. A new card always retakes the camera (unless a finger is mid-drag). A 429 carries the rate limiter's human-check text in `{error}` and is shown as a słowik reply. `Base.astro` binds "/" to focus `#slowik-input` — keep that id.

### Backend specifics

- Bespoke in-memory rate limiter (not express-rate-limit): 20 req/min/IP, then a 429 challenge that must be answered with exactly `"no"`; failure blocks 5 min. It reads `req.body.conversation`, so `express.json()` must run before it.
- MySQL logging via Sequelize is OPTIONAL — only active when `DATABASE_URL` is set; the server must boot and serve `/chat` without a DB.
- All config via env (`backend/.env.example`); never hardcode secrets. `OPENAI_API_KEY` required, `OPENAI_MODEL` defaults to gpt-4o.
- The słowik persona/system prompt lives ONLY in `backend/src/routes/chat.ts` (ASCII "slowik" there by file convention). It is "the clockwork nightingale" — keep the honesty rules (never the man, never human, "that's a song I was never taught") and the confidentiality/prompt-security blocks intact. The frontend never talks to a model vendor.
- Log style: `console.debug/warn/error` with bracketed tags `[CHAT]`, `[DB]`, `[RATE LIMIT]`, `[SERVER]`.

### Deploys

- Frontend: deployed automatically by Cloudflare Workers Builds on push (runs `astro build` and serves `dist/` as Workers Static Assets per `wrangler.jsonc`; `not_found_handling: "404-page"` serves Astro's 404.html) — there is deliberately NO GitHub Actions workflow; do not add one. `npm run build` + `wrangler deploy` remains a manual fallback.
- Backend: build the image from `backend/Dockerfile`, push to the homelab registry, `kubectl apply -k backend/k8s/`. Secrets come from the `chat-api-secrets` Secret (see `backend/k8s/secret.example.yaml` — never commit real values).

## Conventions

- Frontend and backend are both strict TypeScript. Styling is Tailwind utilities inline plus scoped Svelte styles using the OKLCH tokens from `src/styles/global.css` (one amber accent, `--color-accent`). The theme is warm paper (`--color-bg` oklch 0.955) with ink text and one burnt-amber accent; `--color-accent-on-ink` is that accent lifted for the two inverted ink panels (relative-colour syntax with a static fallback), not a second colour. Type roles: `.display` (Newsreader roman 600, -0.02em) for structure — the name, section titles, subheads, the big email; Newsreader italic for titles of pieces and pull quotes; `.mono-label` for apparatus (lowercase by default — add `normal-case` for HEAD, proper nouns, time zones); system sans for body. `body::before` lays a pre-rendered grain tile (`public/grain.png`, alpha noise at 5%) over the page — never a live SVG filter. Motion rides one curve, `--ease-out` (which deliberately shadows Tailwind's default); reduced motion drops keyframes globally and movement transitions per component, but keeps colour/opacity answers.
- All site copy lives in `src/data/site.ts` — components render content, they don't own it. Section heads (§ index, title, meta) live in `site.sections`; the three cover case files are the items flagged `featured`; `site.writing` owns the archive title, description and feed title; `identity.about` exists only for `llms-full.txt`. Do not add fields nothing renders.
- **Interaction grammar is Linear-normalized** (owner's call, 2026-07-05): the arrow cursor everywhere — `cursor: default` on links/buttons globally in `global.css`, never reintroduce `cursor: pointer`; presses are neutral tints (`active:bg-accent/10`, `active:text-accent`), never transforms/scale; every hover/press transition rides the shared tokens (`--default-transition-duration` 140ms + ease-out in `@theme`) — don't hand-roll per-component durations.
- **Mobile-first gutters**: content sections use `px-4 sm:px-6` so their left edge lines up with the frame on phones; tap targets ≥ ~44px (SheetFrame page-index links `py-3`; hero chips, the press-slash link and contact controls `min-h-11`). Keep new sections on this rhythm.
- `prefers-reduced-motion` must always degrade to a calm, static experience (loader hides, bird perches, reveals disabled, the chat camera and card expansion do not animate, the chirp bubble only fades); the global rule no longer zeroes every transition, so gate any new movement transition in its own code.
- No emojis in code.
