# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Layout

Two independently deployed apps live in one repo:

- **Root (`src/`, `public/`)** — Astro 5 static site (Svelte 5 islands, Tailwind 4, MDX content). Built to `dist/` and deployed to Cloudflare Workers Static Assets (`wrangler.jsonc`). This is krystianslowik.com.
- **`backend/`** — Express + TypeScript chat API ("chat-api"). Proxies the słowik chat to OpenAI, rate-limits, optionally logs to MySQL. Deployed to the k3s homelab via `backend/Dockerfile` + `backend/k8s/` manifests, reachable as `chat-api.krystianslowik.com`.

`design/` is design-lab material (interactive HTML studies + the flight-sim harness) — reference, not part of the build. It predates the 2026-07 parrot→słowik rebrand and deliberately keeps its historical `parrot-*` file names (the decision record is `design/slowik-rebrand.md`). `dist/` is build output.

### SEO / discovery layer

Head metadata has ONE owner: `src/components/SEO.astro` (title, description, robots, all OG + Twitter + `article:*`, `theme-color` `#161719`). `Base.astro` passes its reconciled Props (`title, description, type, image, imageAlt, noindex, article, schema`) through to it and separately renders the JSON-LD from the `schema` prop. Do NOT add meta tags anywhere else — widen `SEO.astro` + the `Base` Props together. Structured data (JSON-LD) is built by `src/lib/schema.ts` factories (`homeSchema`/`postSchema`/`writingIndexSchema`) from `site.ts` — every graph embeds the full Person node (validators reject bare `@id` refs across pages). Pages pass `schema={...}`; posts also pass `type="article"` + `article={...}`. `noindex` (404) emits `<meta robots noindex>` and suppresses the canonical.

Discovery files live in `public/` (copied verbatim): `robots.txt` (allow-all incl. AI crawlers + `Sitemap:` → `sitemap-index.xml`), `llms.txt` + `llms-full.txt` (llmstxt.org; **keep llms-full.txt in sync with `site.ts` or delete it** — stale is worse than none), `site.webmanifest` + icon set, `.well-known/security.txt`, an IndexNow key file. The sitemap gets real `lastmod`/priority via `astro.config.mjs`'s `serialize()` (reads post frontmatter dates at config time, since `astro:content` isn't importable there); `trailingSlash: "always"`. RSS is `src/pages/rss.xml.ts`. Fonts are self-hosted via `@fontsource*` `@import`s in `global.css` (NO Google Fonts — the site claims "no trackers"). Scroll reveals are CSS + IntersectionObserver (`html.reveal-armed`, armed by an inline head script only under motion-OK; `.reveal-fallback` 3s failsafe) — GSAP was removed. Owner-only deploy actions (not in-repo): Google Search Console + Bing Webmaster verification & sitemap submit, IndexNow ping after deploy, and confirming Cloudflare's "Block AI bots" is OFF + apex/HTTPS redirects.

## Architecture Notes You Can't See From File Names

### The słowik is a system, not a decoration

The mascot is **the słowik** — a 1-bit amber pixel bird (słowik is Polish for nightingale, and the owner's surname; in copy it is always lowercase with the article, "the słowik" — capitalized "Słowik" means the human). It was rebranded from "the parrot" on 2026-07-04 (decision record: `design/slowik-rebrand.md`; the honesty framing is Andersen's clockwork nightingale — "sings only what it was taught"). NOTE: the sprite ART is still the original crested silhouette (crest, hooked beak, round eye) — a plainer nightingale draft was drawn and then **rolled back by owner preference** (2026-07-05), so the słowik is named for the nightingale but drawn as the original bird. It appears in several places, all driven from two libraries:

- `src/lib/slowik.ts` — sprite geometry rasterised to 1-bit at runtime. The "shader" is `buildBase`: one amber ink, tone via a **4×4 ordered (Bayer) dither** — draw functions paint in greys (`#fff` solid, `#bbb`~75%, `#888`~50%, `#555`~25%) and the quantiser keeps that fraction of each cell, still literally 1-bit-per-pixel amber. Flight poses (`Wing` = `up|mid|down|glide|tuck|flare`): `glide` a long blade held ABOVE the belly-shade band (below it, dither dissolves it into `mid`), `tuck` a lean dive-dart with speed-streaks and a SHORT rib slit (a full-length rib splits the dart into slivers), `flare` the raised-wing airbrake — deliberately the `up` wing polygon (a forward-thrown wing overlaps the head and turns to mush at 1-bit); its identity comes from the fanned tail + feet (the only pose with feet). The flight head is drawn in a counter-rotated sub-frame so the **gaze stays near-level while the body pitches** (real gaze stabilization). Exposes `mountHead` (nav mark), `mountPerched` (404), `mountLoader` (splash), plus `buildBase`/sizes used by the flight engine. `drawFull`/`drawHead` use no grey, so they're unaffected by the multi-level dither. The head sprite is the **original crested design**: two erectile crest triangles (`crestUp` raises them), a hooked beak, a single punched round eye (r2.2), and a downward tail (`tailFlick` displaces its tip in X). A nightingale redraft (crestless, straight bill, ringed eye, up-cocked tail) was tried and reverted — do not re-apply it without the owner asking.
- `src/lib/slowikFlight.ts` — the physics flight engine (exported primitives: `stepFly`, `newFly`, `TUNING`, plus `SONGS`, the speech-bubble song bank, and `FEET`; the dead `WireParrot` class was deleted in the rebrand). **Frame-based integrator at a FIXED 20Hz tick with render interpolation** — never step it per-rAF-frame (display-dependent, runs ~4x fast at 60Hz). Horizontal motion rides the engine's own forward speed; landing uses a parking latch + wire-floor + flare. Every state change must clear `parking`/`forceLand`/`legT` or the bird strands mid-air.
- `src/lib/slowikCompanion.ts` — **THE bird: a page singleton** (`getSlowik()`, guarded on `window.__ksSlowik`). One companion for the whole journey, in viewport coordinates: it perches on `[data-perch]` anchors (section rules, work cards, writing post titles, contact social links, the Experience HEAD row, hero panel, the hero SURNAME — `data-perch="name"`, the OG spot and boot perch, biased +120 so it wins whenever the hero is on screen — telemetry strip, footer), rides them while you scroll, and flies (same engine) to the next perch when its branch leaves the viewport — including mid-flight retargeting when an instant scroll teleports the target away. Perch preference lives in `bias()` (wire 420 > footer 160 > name 120). The bird renders at z 35 — BELOW the sticky nav (z-40): **owner's explicit call — the bird passes UNDER the frosted bar, never over the menu** (do not "fix" this by raising z). The hit box is clipped to below the nav's live bottom edge, so the occluded part of the sprite is not tappable and menu taps always win. **Vertical travel is physical, not a lerp** (`VT` block, redesigned — see the "COMPANION VERTICAL V2" battery): landings DECELERATE to a near-stall via a stopping-distance flare that bleeds the bob's descent to ~0 (not the old accelerate-into-then-clamp thud); climbs are real **flap-bounding** (a burst gains height, wings fold and the body falls a visible scallop, then re-flaps) with peak climb speed < dive so the effort reads; climbing costs forward speed; pitch tracks vertical SPEED (unsaturated); per-leg jitter so repeated hops aren't identical. Touchdown gates on soft rendered speed. **Smoothness layer** (render-only, no physics): takeoff has a 100ms crouch (`crouchT`/`pendingLaunch` → `doLaunch`), the touchdown snap is blended out over ~120ms (`setX`/`setY` decaying render offset — never let landing pop in one frame), and sprites are memoised in `spriteCache` with pitch quantized to 0.04rad (a cache key change is the only thing that redraws — kills per-frame rasterization churn and sub-pixel edge boil). If the only perch is beyond the viewport (perch desert), the bird flies out of sight and settles there silently — never hover-lands at the edge (that teleports).

**Scroll-follow** (`onScroll`/`updateScroll`/`enterFollow`/`launchFollow`/`followTarget`): while you scroll, the bird does NOT chase perch anchors (they scroll away faster than it flies — that made it vanish off the top). Instead it flies to the READING LINE in viewport space (`innerHeight*READ_LINE`, near-stationary) and HOVERS there, visible, chirping to guide — then perches on the nearest anchor when scrolling stops. Take-off needs a real gesture (`scrollAccum > TAKEOFF_PX`, ~1.5 wheel notches, so casual notch-reading just rides the branch) or `perchLeaving()` (direction-aware edge exit). `enterFollow` clears `parking`/`forceLand`/`legT`/`catchT` — hijacking a landing into follow must not strand the bird in flare pose (the strand invariant applies here too). `choose()` early-returns while scroll-follow owns the bird and while `asleep()`; the follow lead is slewed (no reversal yo-yo); reduced-motion never follows (and a mid-session toggle re-settles it). The chat registers a `wire` perch and pulls the bird to new cards; the footer perch sleeps after 23:00 Europe/Berlin. `SlowikChat.svelte` does NOT own a bird — never add a second one. Booted from `Base.astro`; destroyed on `astro:before-swap`.

Tuning changes go through `design/parrot-flight-sim.js` (deterministic node harness, `node design/parrot-flight-sim.js` — the harness keeps its pre-rebrand filename) BEFORE touching `slowikFlight.ts` or the companion's `VT` vertical model. The live model is the **"COMPANION VERTICAL V2"** battery (`runCompanionLegV2`, a 1:1 mirror of `slowikCompanion.updateFlight`); the "COMPANION VERTICAL" (V1) block above it is the pre-redesign baseline kept for A/B. Sprite/pose geometry can't be validated in the sim — render it in-page (drive `window.__ksSlowik`, set `wing`/`rPitch`, `renderSprites()`, screenshot) since `buildBase` needs a DOM canvas. The interactive reference is `design/chat-wire-natural.html`.

### The chat contract

`src/components/SlowikChat.svelte` (the only hydrated island, `client:only`) renders the conversation as cards on a wire with the physics bird. It POSTs `{conversation: [{role, content}]}` to the backend and expects `{message}` back (`src/lib/chatApi.ts`; override endpoint with `PUBLIC_CHAT_API_URL`). The wire is user-scrollable left-right, but it is a **transform camera, NOT a native scroll container** (native `overflow-x: auto` would clip expanded cards vertically and break the bird's anchor math): wheel/trackpad deltaX and pointer-drag (with slop, click-swallowing, velocity smoothing, a hold-means-stop check, and a decay glide; none under reduced motion) move `camX` clamped to the conversation extent — drags may rubber-band 0.3x past the ends and spring back on release. Glide and spring are **time-based (exp decay by dt), never per-frame** — per-frame factors run ~2x hot on 120Hz phones; the motion math is mirrored 1:1 in `design/wire-scroll-sim.js` (node, deterministic) — tune there first, like the flight engine. Also: `.wire-world.manual` kills the 0.6s camera transition while the user owns it, `touch-action: pan-y` on the stage keeps vertical page scroll native, and the bird's wire anchor reads `camX` live so it rides the wire during manual scroll. A new card always retakes the camera (unless a finger is mid-drag). A 429 carries the rate limiter's human-check text in `{error}` and is shown as a słowik reply. `Base.astro` binds "/" to focus `#slowik-input` — keep that id.

### Backend specifics

- Bespoke in-memory rate limiter (not express-rate-limit): 20 req/min/IP, then a 429 challenge that must be answered with exactly `"no"`; failure blocks 5 min. It reads `req.body.conversation`, so `express.json()` must run before it.
- MySQL logging via Sequelize is OPTIONAL — only active when `DATABASE_URL` is set; the server must boot and serve `/chat` without a DB.
- All config via env (`backend/.env.example`); never hardcode secrets. `OPENAI_API_KEY` required, `OPENAI_MODEL` defaults to gpt-4o.
- The słowik persona/system prompt lives ONLY in `backend/src/routes/chat.ts` (ASCII "slowik" there by file convention). It is "the clockwork nightingale" — keep the honesty rules (never the man, never human, "that's a song I was never taught") and the confidentiality/prompt-security blocks intact. The frontend never talks to a model vendor.
- Log style: `console.debug/warn/error` with bracketed tags `[CHAT]`, `[DB]`, `[RATE LIMIT]`, `[SERVER]`.

### Deploys

- Frontend: deployed automatically by Cloudflare on push (Pages CI builds and serves `dist/`, 404 via Astro's 404.html) — there is deliberately NO GitHub Actions workflow; do not add one. `npm run build` + `wrangler deploy` remains a manual fallback.
- Backend: build the image from `backend/Dockerfile`, push to the homelab registry, `kubectl apply -k backend/k8s/`. Secrets come from the `chat-api-secrets` Secret (see `backend/k8s/secret.example.yaml` — never commit real values).

## Conventions

- Frontend and backend are both strict TypeScript. Styling is Tailwind utilities inline plus scoped Svelte styles using the OKLCH tokens from `src/styles/global.css` (one amber accent, `--color-accent`).
- All site copy lives in `src/data/site.ts` — components render content, they don't own it.
- **Interaction grammar is Linear-normalized** (owner's call, 2026-07-05): the arrow cursor everywhere — `cursor: default` on links/buttons globally in `global.css`, never reintroduce `cursor: pointer`; presses are neutral tints (`active:bg-accent/10`, `active:text-accent`), never transforms/scale; every hover/press transition rides the shared tokens (`--default-transition-duration` 140ms + ease-out in `@theme`) — don't hand-roll per-component durations.
- **Mobile-first gutters**: content sections use `px-4 sm:px-6` so their left edge lines up with the nav on phones; tap targets ≥ ~44px (nav links `py-3` below sm). Keep new sections on this rhythm.
- `prefers-reduced-motion` must always degrade to a calm, static experience (loader hides, bird perches, reveals disabled).
- No emojis in code.
